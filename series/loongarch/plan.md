## 0. 一句话

用七集（六篇论文 + 一集总览）讲清一条线：**龙芯真正的资产不是某一颗芯片，而是一个可复用的乱序核心模板、一条被逼出来的指令系统主权之路，以及一套“兼容性优先”的工程方法。** 每一集都要回答三个问题：这一代解决了什么、付出了什么、哪些选择在二十年后仍然成立或已经被证伪。

## 1. 事实基线与史观

### 1.1 真实时间顺序

论文编号不代表顺序。按事实，六篇论文的次序是：

| 集 | 论文 | 年份 | 处理器/主题 |
|---|---|---|---|
| 01 | 龙芯1号处理器结构设计 | 2003 | 龙芯1号，首次流片 |
| 02 | Microarchitecture of the Godson-2 Processor | 2005 | Godson-2，乱序核心模板 |
| 03 | 龙芯2号处理器系统优化关键技术 | 2006 | 同代核心的系统/OS 协同 |
| 04 | Godson-3: A Scalable Multicore RISC Processor with x86 Emulation | 2009 | 四核、NoC、x86 硬件翻译 |
| 05 | 龙芯指令系统融合技术 | 2015 | LoongISA、x86/ARM 双目标翻译 |
| 06 | 龙芯指令系统架构技术 | 2023 | LoongArch、3A5000/LA464 |
| 07 | 总览（不对应单篇论文） | — | 二十年五条线 |

### 1.2 五条贯穿线索（系列的结构骨架）

1. **核心模板**：操作队列复用（2003）→ 64 项物理寄存器映射 / 16 项保留站 / 32 项队列（2005）→ GS464 64 项队列（2009）→ GS464E 128 项映射、三组保留站、128 项队列（2015）→ LA464 保留 128 项映射、3×32 发射队列（2023）。乱序骨架在 2005 年基本定型，之后主要是容量、级数、向量宽度和工艺的变化。
2. **指令系统**：MIPS32 兼容（2003）→ MIPS64（2005/2006）→ MIPS64 + x86 硬件翻译（2009）→ LoongISA + x86/ARM 翻译（2015）→ LoongArch 自主指令系统 + LBT（2023）。
3. **二进制翻译**：无（2003/2005/2006）→ x86 单目标硬件原型（2009）→ x86+ARM 双目标系统融合（2015）→ LATM/LATX/LATA 三方向翻译器（2023）。翻译从来不是“原生”，2023 年论文给出的 x86 整数/浮点效率约 65.5%/70.3%，剩余差距来自不可约语义、标志位生成和地址转换。
4. **存储层次**：8KB 两路阻塞式（2003）→ 64KB 四路非阻塞 + 片外 8MB L2（2005/2006）→ 片上 512KB L2 + 目录一致性（2009）→ 三级片上缓存 + 目录 MESI（2015）→ 64KB L1 + 256KB victim + 16MB 共享 L3（2023）。
5. **并行**：ILP（2003/2005）→ ILP + 整数 SIMD（2006）→ TLP/NoC（2009）→ 128 位向量（2015）→ 128/256 位向量（2023）。

### 1.3 路线判断

- 目标不是做“能用的便宜芯片”，而是以自主版权的高性能通用 CPU 为龙头，带动 IC 产业。
- 三条启动原则：高起点、兼容性作为生命线、分阶段验证（架构模拟 → FPGA → 流片，争取一次流片成功）。
- “先借后还”：主频/工艺落后时，用微架构和软硬协同突破；MIPS 授权期搁置指令系统主权，积累工具链、翻译和移植能力，再把能力内化为自有指令系统。
- **可复用资产是乱序核心模板，不是某一颗芯片**；后续几代是模板复用 + 参数演进。
- 硬件辅助翻译只下沉最高频、最昂贵的结构性语义缺口（标志位、栈式浮点寄存器、两级地址转换、间接跳转目标、寄存器稀缺、特权级切换），其余留给软件。
- 生态先于指令系统定型：3 个编译器、3 个虚拟机、3 个翻译器，是对单一生态锁定的冗余。

### 1.4 必须诚实写出的限制

- MIPS 授权把指令系统主权推迟到 2023 年；早期缓存、编译器、生态短板反复压住性能。
- 2009 年论文里的三个“可重构方向”（可重构核心槽位、NUCA 动态 L2 迁移、可重构 DMA）与 TFLOPS 多核研究，没有在 2015/2023 主线中重现，**不能声称已落地**。
- 六篇论文只覆盖 2003/2005/2006/2009/2015/2023；中间迭代和第三方基准不在范围内。
- 跨论文数字的平台、编译器、基准不同，**禁止画成单调曲线**。3A5000 相对 3A4000 的提升包含缓存与内存接口，不全是指令系统的功劳。
- 2023 年论文中“2025 年左右消除单一指令系统壁垒”是计划，不是已完成事实。

## 2. 七集设计

每一集的固定结构（约 7–10 分钟）：

1. **冷开场（30–45 秒）**：一个当时的真实困境或一个反直觉数字。
2. **历史位置（60–90 秒）**：这一代之前卡在哪，为什么现在做。
3. **论文的核心设计（3–4 分钟）**：用图、时序、数据把机制讲透；至少一个可运行实验或原文图表。
4. **代价与反证（60–90 秒）**：哪里没做好，哪些数字不能直接比。
5. **产品与回声（60–90 秒）**：对应产品、当时的评价、后来的呼应/批评。
6. **交给下一集的问题（20–30 秒）**。

### 01 龙芯1号：先证明“能跑”（2003）

- 钩子：2002 年，一支以研究生为主的队伍，第一次流片就要让 Linux 跑起来；当时中国没有可用的自主通用 CPU。
- 论点：龙芯1号的历史意义不是性能，而是**一次流片成功 + 兼容 MIPS + 能跑真实操作系统**，把“能不能做”变成“能做，但 Cache 太小”。
- 核心证据：0.18μm、约 200–250MHz、单发射乱序、操作队列复用、精确例外、8KB 级缓存；论文自己承认 Cache 过小、组织方式待改进。
- 实验（可在本机跑）：写一个**操作队列复用/精确例外**的周期级小模型，对比“顺序五级流水”与“小窗口乱序”在同一依赖链上的停顿；再用一个故意在分支后写寄存器的例子，演示精确例外为什么必须等所有前序指令提交。输出每周期状态图，作为片子动画数据。
- 产品与回声：龙芯1号/后续 IP；当时的“中国芯”舆论与性能质疑要分开讲，不能把汉芯事件混为一谈。评价材料优先级：当年的鉴定/测试报告 > 学术引用 > 媒体报道。
- 交给下一集：单发射、Cache 小、主频低——下一代替换的不是勇气，是**微架构模板**。

### 02 Godson-2：把乱序核心做成模板（2005）

- 钩子：2005 年，Intel/AMD 已经在 3GHz 以上；一颗 0.18μm、频率低得多的中国芯片，凭什么敢用“四发射、乱序、物理寄存器重命名”？
- 论点：Godson-2 的真正遗产是**一套可参数化复用的乱序核心模板**：物理寄存器映射 + 保留站 + 非阻塞 Cache，使“低主频、高 IPC”成为可能；这套骨架被后续三代直接继承。
- 核心证据：64 位、四发射、64 项物理寄存器映射、16 项保留站、32 项队列、非阻塞 Cache、0.18μm 六层金属；论文给出的频率/功耗/面积与 SPEC 数据要逐项入 claims ledger。
- 实验：写一个**重命名 vs 不重命名**的依赖模拟器，输入一段带假相关的指令序列（如反复写同一架构寄存器），统计发射停顿；再扫物理寄存器数量 32/64/128，画 IPC 曲线，解释为什么 64 项在当年是合理点。
- 产品与回声：龙芯2号/2E/2F 与早期龙梦整机；当时评价集中在“能跑 Linux 桌面，但软件少、主频低”。要区分“微架构效率”与“整机可用性”。
- 交给下一集：核心不再是最短板，**存储系统和操作系统支持**成为新瓶颈。

### 03 龙芯2号系统优化：核心之外的战争（2006）

- 钩子：同一代核心，为什么换一套系统软件和缓存组织，性能能再涨一截？
- 论点：这一代的关键不是再加宽流水线，而是**软硬协同**：虚拟索引缓存别名、TLB 失效、非对齐访问、DMA/一致性，这些“不酷”的问题决定了真实程序跑多快。
- 核心证据：MIPS64、约 405MHz、L1 64KB 四路、片外 8MB L2；论文给出的优化项与加速比逐项入 ledger，并注明测试条件。
- 实验：写一个**虚拟索引缓存别名 + 页着色**模拟器：同一物理页映射到两个虚拟地址，测量别名冲突与页着色后的 miss 变化；再补一个非对齐访问的陷入/模拟成本模型。两个实验都可完全在 Python 里跑，输出热力图和时序。
- 产品与回声：龙芯2E/福珑迷你电脑等；评价要引用真实用户/媒体对“便宜 Linux 盒子”的反馈，不要只引用发布会。
- 交给下一集：单核 IPC 的边际收益变小，**多核与兼容性**成为新叙事。

### 04 Godson-3：四核、NoC 与 x86 硬件翻译（2009）

- 钩子：2009 年，四核龙芯要跑 x86 软件；但“硬件翻译 x86”到底是卖点还是包袱？
- 论点：Godson-3 用 **NoC + 目录一致性** 解决多核扩展，用**有限的硬件辅助**解决 x86 翻译中最贵的语义缺口；它不是“把 x86 塞进芯片”，而是把翻译器最痛的部分下沉。
- 核心证据：65nm、约 1GHz、四核 GS464、NoC、目录一致性、x86 硬件翻译；四核 2008 年流片。论文中的可重构方向要标注“研究性，未在后续主线确认落地”。
- 实验：写一个**四核目录 MESI vs 总线监听**的流量模型，扫核心数与共享度，画一致性流量/延迟；再写一个 x86 标志位翻译的成本模型（eager vs lazy），说明为什么硬件只该辅助高频路径。
- 产品与回声：龙芯3A1000 等；x86 翻译的实际可用性要引用第三方测试/用户反馈，若找不到可靠评价就明确说“缺少公开可复现数据”，不得编造。
- 交给下一集：多核有了，但指令系统仍是 MIPS；**兼容性从“翻译”升级为“系统融合”**。

### 05 龙芯指令系统融合：兼容性是生命线（2015）

- 钩子：2015 年，龙芯一边说“自主”，一边把 x86/ARM 翻译做进硬件；这到底是妥协还是策略？
- 论点：LoongISA 阶段的核心是**用系统级融合换取生态时间**：双页表 TLB、guest 特权级、x86/ARM 双目标翻译，把“能跑别人的软件”做成可持续能力，同时为自有指令系统积累工具链。
- 核心证据：3A1500/GS464E、12 级流水、三级片上缓存、双页表 TLB、guest 特权模型；2014.09 流片。
- 实验：写一个**两级地址转换**模型：影子页表 vs 双页表 TLB，扫 TLB 命中率与缺页率，画每次访存的平均转换开销；用数据解释为什么硬件必须支持 guest 页表。
- 产品与回声：3A1500/3A2000/3A3000 一线；评价重点：单核性能、桌面可用性、生态缺口。引用要区分“能启动”与“能日常使用”。
- 交给下一集：兼容性策略走到尽头——**要真正自主，必须换指令系统**。

### 06 LoongArch：把指令系统主权拿回来（2023）

- 钩子：2023 年，龙芯终于有了自己的指令系统；但“自主”之后，性能差距和生态差距就自动消失了吗？
- 论点：LoongArch 的真正变化是**指令系统、编译器、虚拟机、翻译器可以一起设计**；3A5000/LA464 是顶层重构 + 16MB L3 + DDR4-3200 的组合，不是单一 ISA 的胜利。翻译仍是过渡，2023 年论文自己给出 x86 效率约 65.5%/70.3%。
- 核心证据：12nm、2.3–2.5GHz、16MB 共享 L3、DDR4-3200、三方向翻译 LATM/LATX/LATA、3 编译器/3 VM；跨代性能数字必须注明平台与基准。
- 实验（分级）：
  - A 级（本机可跑）：写一个**翻译器分派开销**模型，对比直接执行、BT 基本块、带标志位优化三种路径的每指令开销；只用模型，不冒充真机。
  - B 级（若有 qemu-loongarch64）：跑一组微型 C 基准的 native x86 vs qemu-user LoongArch，明确标注“QEMU 模拟，不代表 3A5000”。
  - C 级（无环境）：逐条引用论文中的 SPEC/翻译效率表，配原文截图，不跑分。
- 产品与回声：3A5000（2021）、3A6000（2023 后）；重点找 Phoronix、极客湾等第三方评测的**具体结论与批评**（IPC、内存、生态、价格），找不到就降级为“论文自述”，并标注。
- 交给下一集：把所有线索收拢——**哪些选择赢了，哪些只是延迟了问题**。

### 07 总览：二十年一条线（约 5–6 分钟）

- 不重复单集细节，只做三件事：
  1. 用一张**五线时间轴**把六集串起来（核心模板/ISA/翻译/存储/并行）。
  2. 给出**三胜三负**：胜在模板复用、分阶段验证、兼容性换时间；负在工艺/主频长期落后、软件生态、翻译天花板。
  3. 回答“今天怎么看龙芯”：它证明了一条非西方路径可以做出可用的通用 CPU，但离“全面替代”还有距离；2025 年消除单一 ISA 壁垒是计划，不是结论。
- 形式：数据可视化 + 前六集画面回闪 + 一段克制的收尾；不新增实验。

- `build/`：数据生成与实验脚本；derive 命令用 pack 相对路径。
- `docs/`：本集 plan、script、sources、experiment 记录。
- `delivery/`：srt/chapters/ffmeta/cover/report；mp4 忽略。

### 3.1 挂载与隔离

- 引擎 `films.mjs sync` 把每集 `src`→`src/<id>`、`data`→`data/<id>`、`assets/public`→`public/<id>`。

- 隔离规则：一集只能读自己的 `data/<id>/`、系列共享 `data/series/loongarch/`、设计契约；不能读别的集。跨集引用通过共享组件/共享数据，不复制事实。
- 跨集一致性由 `shared/data/timeline.json` 与 `shared/data/threads.json` 提供；每集只能引用，不得手写另一套时间线。

## 4. 实验与证据分级

每集的“实验”必须标级，禁止把模型/模拟说成真机：

- **A 级（本机可复现）**：Python/Node 模拟器、算法基准、缓存/一致性/翻译开销模型。数据写入 `data/*.json`，脚本在 `build/`，report 里记录输入哈希与运行命令。
- **B 级（模拟环境）**：QEMU、FPGA、第三方模拟器；必须标注“模拟，不代表目标芯片”。
- **C 级（原文引用）**：论文图表、厂商数据、第三方评测；必须给页码/URL，截图入 `assets/public/` 并注明来源与授权。

每集至少一个 A 级实验；若确实不可行（例如 E6 无 LoongArch 硬件），用 A 级“开销模型”+ C 级原文表，**不伪造真机跑分**。

证据链：

- `data/claims.json`：屏幕上的每个关键数字一行，含 value、unit、source（paper/URL/page/quote）。
- `data/paper.txt`：论文原文抽取（可检索），用于 claims_check 的引文核对。
- `docs/sources.md`：人类可读的来源表，含授权/引用方式。
- 产品评价：优先第三方实测/长期使用报告；厂商稿只作背景。找不到就写“缺少公开可复现评价”，并把它作为事实写进片子。

## 5. 生产顺序与门禁

### 5.1 顺序

1. **S0 系列骨架**：series.json、plan.md、shared 组件/数据、sources/fact-ledger 模板；check 通过。
2. **S1 证据**：六篇论文抽取、claims ledger 骨架、时间线/五线数据、产品评价来源清单；事实审计（每条关键数字有出处）。
3. **S2 E01**：先做一集完整样片，验证系列视觉/声音/节奏/实验管线；验收后再批量。
4. **S3 E02–E06**：按 01→06 顺序逐集生产；每集完成即交付、验收、提交。
5. **S4 E07 总览**：复用前六集数据与画面，最后生产。
6. **S5 系列交付**：封面、合集、简介、章节、B 站投稿信息；全系列一致性复核。

### 5.2 每集门禁（内容仓 + 引擎）

内容仓：

- `node tools/check.mjs` 通过；film.json 与 series.json 一致。
- claims：每个屏幕数字有 quote/value；paper.txt 中存在引文。
- derived：派生文件不被 git 跟踪；生成器可重跑。
- 资产：所有 staticFile 路径存在；授权/来源记录。
- 文档：plan/sources/experiment 三件套齐全。

引擎：

- `node scripts/films.mjs sync/check --strict`。
- `node scripts/qa/derive_data.mjs --film=<id>` 可重跑。
- `npx tsc --noEmit`；film_coverage/film_isolation 通过。
- `node scripts/make.mjs --film=<id>` 成功；report.json 全绿。
- 时长、响度（I −16.5…−13，TP ≤ −1.5）、flicker、静帧 lint 通过。
- 人工审片：事实、逻辑、节奏、字幕、封面四项签字（记录在 production-log）。

### 5.3 系列一致性门禁

- 开场 5 秒内出现系列标识/集号；结尾 10 秒出现下一集钩子。
- 同一术语表（`shared/data/glossary.json`）；同一时间线数据；同一配色/字体/版式。
- 每集至少一次“回指上一集”，一次“留给下一集”。
- 旁白音色、语速、字幕风格全系列一致。

## 6. 验收标准（系列级）

A. **事实**：六篇论文的关键数字 100% 有出处；产品评价 100% 有来源或明确“无公开数据”；无跨平台数字被画成单调曲线。
B. **逻辑**：按真实时间顺序；每集回答“解决什么/付出什么/留下什么”；总览能复述五条线。
C. **工程**：七个 pack 可独立挂载/渲染；clean clone + sync 可复现；每集 report.json 可审计；脚本/数据/资产在 video_project 内闭环。
D. **完成度**：七集视频 + 七套交付物（mp4/srt/chapters/cover/report）+ 系列合集信息；B 站投稿完成。
E. **诚实**：至少明确写出三处失败/限制（Cache 小、MIPS 授权延迟、翻译天花板），不得只讲成功。

## 7. 与 gen24-admin 的分工

- `video_project/series/loongarch/plan.md`（本文）：逐集设计、工程结构、实验、门禁；制作时以本文为准。

## 8. 风险与回退

| 风险 | 触发 | 回退 |
|---|---|---|
| 事实错误 | claims 审计失败 | 停拍该集，回论文原文；未核实数字不上屏 |
| 实验不可行 | 无硬件/模拟器 | 降级为 A 级开销模型 + C 级原文表，明确标注 |
| 产品评价缺失 | 找不到可靠来源 | 写“缺少公开可复现评价”，不编造 |
| 工期失控 | 单集超过预算 | 先做 8 分钟版，删次要场景；总览最后做 |
| 引擎/内容耦合回归 | 引擎出现片名 | 回到 docs/52 的边界测试，修引擎 |
| B 站投稿失败 | win-admin 缺口 | 保存投稿草稿/字段清单，人工接管；在最终报告记录 |
